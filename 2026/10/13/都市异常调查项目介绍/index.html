都市异常调查：把 CoC 的调查感做进竖屏微信小游戏

发表于2026-10-13|更新于2026-10-13|项目介绍

都市异常调查：把 CoC 的调查感做进竖屏微信小游戏

跑过 CoC（克苏鲁的呼唤）的人大概都有这种体验：最紧张的不是打到 BOSS 那一回合，而是你意识到线索就摆在你面前、但你还没读懂它的时候。这个项目想做的，就是把那段时间压缩成单手、竖屏、几分钟一局的微信小游戏。

一句话定位：现代都市背景的竖屏 3D 回合制调查小游戏，魔幻 + 仙侠 + CoC 式调查感；氛围不是纯恐怖，而是「日常城市里出现异常事件」的悬疑感。工程代号 web_rpg，启动页上暂时写着 《都市异常调查》。

这是个什么游戏

核心循环一句话：调查 → 线索 → 战斗 → 理智变化 → 结算。

环节 玩家做什么 为什么要有它
🔍 调查 在分区城市地图（大学城、旧城区）里点异常点，进调查场景 把「读场景」变成主要动作，而不是只看剧情弹窗
🧩 线索 攒线索；线索能降低敌人防御、提前暴露弱点、减少理智消耗 让「看得懂」这件事有实际收益
⚔️ 战斗 竖屏 3D 回合制：站位、技能、异常状态、BOSS 弱点 策略来自信息差，而不是来自数值堆叠
🧠 理智 用强力技能会掉理智；理智过低触发异常状态 强制玩家权衡「这一发要不要打」
🎲 灵感检定 随机触发，成功给线索或增益，失败掉理智 给回合制加一点跑团的不确定感
📜 结算 经验、道具，理智恢复或继续污染 让上一局的后果带进下一局

角色卡先用一版简化 CoC 属性：力量、敏捷、智力、灵感、理智，再加一条修为/灵力（给道士和仙侠侧内容留口子）。可以直接从 CoC 人物生成器导入简化卡，也可以游戏内创建；玩家同一时间只操作一个角色，其余角色作为自动行动的队友。

职业构想是五个，第一版只做两个：

职业 战斗玩法 实现难度 版本
战士 普通攻击 / 防御 低 第一版
道士 卡牌抽打 / 驱散 中 第一版
猎人 射击 · 弹珠小游戏 高 第二版
法师 魔法经验 · 三消 高 第二版
奇械师 堆叠消除 高 第二版

敌人按题材分五类，第一批只做辨识度高的：

末班地铁乘客、电梯陌生人。成本最低的一批：不需要新模型骨架，靠场景氛围 + 行为异常（该有人时没人、该关门时不开）制造不适感。

走火入丹的散修、失控法器。用来承接「修为/灵力」这条属性线。

契约恶魔、炼金傀儡。第一版先不做，避免同时维护三套美术规则。

诅咒手机、会说话的自动售货机。最省事也最容易传播的一类和「日常物件不对劲」的题材天然适配截图分享。

影中人、主线 BOSS 无面者。留给第一版的收尾，也是唯一带弱点机制的敌人。

三条不可让步的体验铁律

这三条是我给自己划的红线，来自「不要把它做成需要研读规则的桌游」。任何功能和它冲突，先砍功能。

  1. 首次进入即玩：启动后直接进试玩关卡，用模板角色，不建角色、不选服、不看剧情动画。
  2. 关键路径零阅读：从进游戏到打完第一场战斗，不需要读一句文字。技能用图标不用长文本，理智用颜色条，暂停按钮常驻。
  3. 单手、可暂停、短局：回合制没有实时物理，随时能中断，单局时长控制在一两分钟内。

开发路径：十个阶段

排期原则只有一句：先跑通核心循环 → 再做关卡内容 → 再做养成和联机 → 最后优化变现。所以第一版是 Demo，不是完整游戏。

开发路径

1—3 天 · 阶段 0 项目定型

先不写代码，把范围锁死：微信小游戏 · 竖屏、Cocos Creator、体素美术（MagicaVoxel 建模导出 glb）。第一版目标：一个主角 + 三个队友、两个区域、五个异常事件、一个主线 BOSS、完整战斗循环。不做什么同样写进文档：完整开放主城、复杂建造、多人实时联机、完整 CoC 规则、复杂剧情分支。

2—5 天 · 阶段 1 模板项目

竖屏分辨率、场景切换（启动页 → 主界面 → 战斗场景）、基础 UI 骨架、资源目录、调查/战斗/结算三态状态机。这一阶段唯一的验收标准是：点「开始」能进到一个空白战斗场景。

5—10 天 · 阶段 2 战斗原型

第一版最重要的部分。只做一个主角 + 一个敌人：回合制流程（我方 → 敌方 → 结算）、四个技能按钮、理智值、灵感检定、简单敌人 AI（普攻 / 随机技能 / 血量低于阈值换招）。

5—8 天 · 阶段 3 调查与线索

城市分区地图、每区域 2—3 个异常点、调查得线索、线索反哺战斗、战斗结算影响理智。剧情分支先不做，只做「线索多 → 战斗简单；线索少 → 战斗难」。

5—7 天 · 阶段 4 角色与角色卡

简化版 CoC 角色卡、创建角色、选职业、战斗内显示状态、队友自动行动。更换队友、真人队友、职业转换推到后期。

7—12 天 · 阶段 5 关卡内容

大学城 2 个异常事件 + 旧城区 2 个 + 主线 BOSS 1 个，每个事件都含调查点、线索、战斗、结算。剧情走明确单线：大学城出现异常 → 旧城区线索指向同一源头 → 主角团发现旧神眷属 → 击败 BOSS → 留更大悬念。

3—5 天 · 阶段 6 主界面与新手体验

把「首次进入快、不需要读文字」落到界面上：模板角色直接开局、按钮大、图标清楚、色条理智、随时暂停、结束直接回地图或结算页。

并行推进 · 阶段 7 体素美术管线

和程序并行：MagicaVoxel 建模 → 导出 glb → 导入 Cocos Creator → 验证动画/材质/光照 → 统一配色 → 大学城、旧城区各一个小型体素场景。第一版不求精细，只求风格统一、识别度高。

3—5 天 · 阶段 9 测试与打包

找同学试玩，重点看六件事：首次进入够不够快、不读文字能不能玩、战斗能不能单手、理智系统好不好理解、线索是否真的影响战斗、包体是否超标。然后根据反馈删复杂度，而不是继续加系统。

第二版再做 · 阶段 8 养成与主城

年龄系统、人生履历、职业转换、赚钱、主城自由移动、场景破坏、建造、GTA 式探索。这些内容都很好，但都会拖慢 Demo；第一版只需要一个「能接任务、换角色、看线索、进关卡」的简单主城。

现状对照：走到哪一步了

截至发稿：阶段 0 已完成，阶段 1 进行中，阶段 2 的战斗原型还没动。下面这份清单是从工程里数出来的，不是计划。

  • 范围锁死，「第一版不做」清单成文
  • Cocos Creator 3.8.8 工程建立，目录分层（Scenes / Scripts / Source / Models / Materials / Effects / Textures）
  • 竖屏设计分辨率 720×1280、适配宽度（写进 settings/v2/packages/project.json）
  • 启动页 Splash.scene：标题副标题淡入 → 后台预加载 → 「开始调查」→ 黑场淡出切 3D 场景
  • 第一个 3D 场景能进（目前仍是模板的 ThirdPersonCharacter.scene）
  • 场景文件与 .meta 的生成校验脚本链
  • 主界面、战斗 UI（头像 / 理智条 / 技能按钮）
  • 调查 / 战斗 / 结算状态机
  • 微信小游戏首次构建（还没有 build/ 目录）
  • 体素角色与体素场景（当前模型是模板的 highPoly_female.fbx、Stairs.glb、Terrain.terrain、600KB 天空盒 HDR）

工程结构大致是这样：

点开看：启动页里那几个「防翻车」的小设计

这些东西不值一行代码的炫耀，但每一条都对应一个真实会发生的事故：

  • 启动页故意不引用任何大贴图。 模板 3D 场景的天空盒 HDR 有 600KB，启动页一个都不加载，整页只有一张 64×64 的纯白图，所以首屏很快。
  • 贴图丢了也不会白屏。 UiKit.ensureSolidSprites() 在启动时检查所有 Sprite，没有 SpriteFrame 的自动补上引擎内置的 white-texture，颜色由 Sprite 自己的 Color 决定。
  • 预加载失败不卡死。 超时或失败会提示「场景未加入构建列表」，玩家仍然能手动点进场景——对小游戏来说，卡在第一屏等于直接流失。
  • 进度条「编辑器所见即运行时所得」。 Bar 节点锚点写死 (0, 0.5)、x 取负半宽，正好是 cc.ProgressBar 运行时会摆的位置，不会有跳变。
  • Splash.scene 是脚本生成的，不是手敲 JSON。 Cocos 场景里脚本组件的 __type__ 用的是压缩 uuid，tools/cocos-uuid.js 负责压缩与解压，validate-scene.js 校验引用、父子关系、Canvas 与相机连线、图层可见性。改界面请在编辑器里改，重跑生成器会覆盖手动调整。

前身原型：一个 Three.js 的单文件 3D RPG

在定下 Cocos + 微信小游戏之前，我先用 Three.js 写了一个单文件原型验证「第三人称探索 + 回合制战斗」的手感。它跑通了几件事：靠近敌人自动切入回合制、回合内四个行动选项、HP/MP/EXP 与任务计数、死亡复活。

它的局限也很明确：吃键鼠（WASD + 鼠标视角），手机上基本只能看个意思；没有调查层、没有理智系统、没有线索；模型是程序几何体拼的；还依赖 CDN 加载 three.js（three@0.160.0 的 UMD 包，官方已把 three.min.js 标为 deprecated，r160 还能用，但真要长期挂着得换成 ES Module）。它的价值到「证明回合制切换成立」为止就结束了，主角、敌人、地图在新项目里全部推倒重来。

我给自己定的三条戒律

  • 一次只加一个系统，先让它能玩，再让它好玩。
  • 想加年龄 / 主城 / 建造 / GTA 式探索时，写进第二版清单，不动第一版。
  • 试玩反馈回来后删复杂度，而不是继续加系统。

后续路线图

  • 启动流程与竖屏配置
  • 战斗循环（一个主角 + 一个敌人）
  • 理智值 + 灵感检定
  • 调查 + 线索（含线索对战斗的实际影响）
  • 角色卡 + 两个职业
  • 两个区域 + 五个异常事件
  • 主线 BOSS 战（弱点机制 + 理智压力）
  • 主界面与新手流程
  • 体素美术统一（MagicaVoxel → glb 管线）
  • 微信小游戏构建与包体/首屏实测
  • 第二版：养成、主城、联机

四个目前还没答案、需要在阶段 2—3 里验证的风险：微信小游戏的包体上限（3D 场景 + 天空盒很容易超）；低端机性能（Draw Call、骨骼数、内存峰值，目标是稳定 30fps）；理智系统能不能被看懂（不掉血而掉一个看不见的条，玩家可能完全不 care）；题材审核（都市怪谈 + CoC 的恐怖氛围在小游戏平台的内容规范下要克制到什么程度）。

如果你更想快点看到一个能发给同学的东西，那还有更狠的砍法：一个主角、一个队友、一个区域、三个异常事件、一个 BOSS。按这个范围，一两周就能拿出可试玩 Demo。

最后

第一批玩家就是我的同学——所以题材必须让他们有共鸣、能分享、单局短、能互坑互夸。这个项目能不能成，不取决于我设计了多完整的系统，而取决于他们愿不愿意在课间把那三分钟打完。

线索越多，战斗越简单；规则越少，玩家越多。
